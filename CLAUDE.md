## 1. Game concept

**Awas Ada Pocong** ("Watch Out, There's a Pocong") is a horror-comedy multiplayer betting game. Each round, players bet TKN tokens on which room of an isometric 3D haunted mansion the Pocong ghost will enter. The Pocong picks a random room; players whose rooms were NOT chosen win. Players whose room was chosen lose — they were "found" by the ghost.

- Genre: Indonesian horror-comedy (Pocong is a traditional Indonesian ghost — a corpse wrapped in white burial cloth that hops around).
- Visual tone: B&W cartoon isometric dollhouse with red blood-splatter accents; Creepster horror font; MeshToonMaterial with thick black outlines.
- Language: UI labels mostly Indonesian.
- Multiplayer: up to N players per round; all bets are visible as player tokens on the 3D map.

## 5. Visual spec — Three.js scene

### Camera

- `THREE.OrthographicCamera`, aspect-correct frustum driven by `camState.viewSize`.
- ISO elevation: `35.264°` (true isometric angle).
- Default `viewSize = 16`; clamp `[10, 40]`.
- Camera positioned at `target + r * (sin(az)*cos(elev), sin(elev), cos(az)*cos(elev))` where `r = viewSize * 2.5`.
- `target` clamped to `[-3, 15]` on both X and Z.

### Geometry constants

```js
const GRID_SPACING = 4.0;   // must equal ROOM_W — no gap between rooms
const ROOM_W = 4.0;
const ROOM_D = 4.0;
const WALL_H = 2.8;         // tall walls = dollhouse silhouette
const WALL_T = 0.12;        // wall thickness
const DOOR_GAP = 1.2;       // doorway opening width
const DOOR_H = 2.1;         // doorway opening height
const SEG_W = (ROOM_W - DOOR_GAP) / 2;  // = 1.4 (wall segment beside doorway)
const LINTEL_H = WALL_H - DOOR_H;       // = 0.7 (lintel above doorway)
const CEIL_DEPTH = 0.65;    // depth of ceiling edge panel
```

### Toon shading

`MeshToonMaterial` with a 4-stop `CanvasTexture` gradient map (4×1 px canvas: `#1a1a1a → #777 → #ddd → #fff`, `NearestFilter`). All room geometry uses this material.

### Lights

```js
AmbientLight(0xffffff, 0.35)
DirectionalLight(0xffffff, 1.0)  @ position (10, 20, 10), castShadow
DirectionalLight(0xffffff, 0.3)  @ position (-10, 10, -10)
```

Two directional lights are critical — they produce different luminance on adjacent faces, making the isometric cube read as 3D under toon shading.

### OutlinePass

```js
outlinePass.edgeStrength  = 6.0;
outlinePass.edgeGlow      = 0;
outlinePass.edgeThickness = 2.5;
outlinePass.visibleEdgeColor = '#000000';
outlinePass.hiddenEdgeColor  = '#000000';
```

### Materials

| name | color | notes |
|---|---|---|
| `matFloor` | `0xe0e0e0` | Room floors |
| `matWall` | `0xf0f0ea` | All wall segments |
| `matFurn` | `0x999999` | Generic furniture |
| `matDark` | `0x444444` | Dark furniture accents |
| `matCorr` | `0xb0b0b0` | Corridor floor (darker than rooms) |
| `matCeil` | `0x888888` | Ceiling edge panels |

### Dollhouse wall system

Each room (`buildRoom()`) builds only its **negX** and **negZ** walls (shared with neighbours to the left/above). The rightmost column (gridX=3) also gets a posX exterior wall; the bottom row (gridZ=3) also gets a posZ exterior wall. Interior walls are never built — adjacent rooms share the wall mesh of the lower-index room.

Shared walls get a **doorway** opening when the neighbouring room exists:
- `hasCellNegZ = gridZ > 0` → negZ wall uses `doorwayWallGroupX(ROOM_W)` instead of solid
- `hasCellNegX = gridX > 0` → negX wall uses `doorwayWallGroupZ(ROOM_D)` instead of solid

`doorwayWallGroupX(totalLen)`: two wall segments flanking the doorway on X-axis walls; a lintel above.
`doorwayWallGroupZ(totalLen)`: same but for Z-axis walls.

Ceiling panels: one thin `BoxGeometry` slab per visible wall face, positioned at `y = WALL_H + 0.045`, depth `CEIL_DEPTH`. Visibility matches wall visibility.

### Wall visibility (dollhouse view)

`updateWallsForAzimuth(az)` snaps az to nearest 90° and shows the two walls that face toward the camera:

| azimuth (snap) | visible walls |
|---|---|
| 0° (NE) | negX, negZ |
| 90° (NW) | posX, negZ |
| 180° (SW) | posX, posZ |
| 270° (SE) | negX, posZ |

### Floor overlays per room

Each bettable room has two overlapping floor planes at y=0.06–0.07:
1. **Red overlay** (`MeshBasicMaterial`, color `0xff0000`, starts opacity 0) — general win-room tint.
2. **Blood splatter** (`MeshBasicMaterial`, `CanvasTexture` of irregular red ellipses, starts opacity 0) — revealed at `opacity=1.0` when that room is the winner.

### Blood splatter texture (`makeBloodSplatter()`)

256×256 canvas, drawn once at load and shared via `sharedBloodTex`. 9 angled ellipses radiating from center (color `#cc0000`), a center pool ellipse (`#aa0000`), and 6 small secondary drops. Created using `ctx.ellipse()` with `ctx.save()/restore()` for rotation.

### Hover overlay

A single `hoverOverlay` mesh (`PlaneGeometry`, `MeshBasicMaterial`, white, opacity 0.13) repositioned each frame to the hovered room center. Only visible during active rounds before the player bets.

### Pocong ghost sprite

`THREE.Sprite` loaded from `/assets/pocong.jpg` at scale `(1.1, 1.6, 1)`. During active rounds: animates along the corridor path `(4,12) → (8,12) → (12,12) → (12,8) → (12,4) → (12,0)` at speed 0.003/frame. Also bobs on Y by `sin(t*2) * 0.09`. On completed rounds: freezes at winner room center.

### Player tokens

Canvas-drawn sprites (64×64) with initial letter, grey fill, white stroke. Placed in a spiral around the room center. Up to 50 tokens shown per round. Greyed to `0x444444` in winner room on completion.

## 6. Camera controls

All camera logic lives in `camState`:
```js
const camState = {
  target: new THREE.Vector3(6, 0, 6),
  viewSize: 16,
  liveAzimuth: 0,    // current (lerping) azimuth degrees
  azimuth: 0,        // last snapped azimuth
  snapTarget: 0,     // snap destination
  isSnapping: false,
};
```

| Action | Input |
|---|---|
| Pan | Left-drag (world-space XZ plane raycaster) |
| Zoom | Scroll wheel (Δ `viewSize`, clamped `[10,40]`) |
| Rotate | Right-drag (Δazimuth `* 0.35 deg/px`) |
| Snap on release | `snapAzimuth()` → nearest 0/90/180/270° |
| Touch pan | 1-finger drag |
| Touch zoom | 2-finger pinch |
| Touch rotate | 2-finger twist angle |

`snapAzimuth()` sets `isSnapping=true`; the animate loop lerps `liveAzimuth → snapTarget` at factor 0.14/frame.

### Bet panel

Five `<button class="bet-chip" data-amount="N">` elements + `#btn-decrement` (−) / `#btn-increment` (+). `selectedBetAmount` tracks current selection (default 1000). Active chip gets `.active` class (gold border/background). Chips are disabled when round not active or bet already placed. Clicking a chip updates selection; clicking a room shows `#confirm-chip`.

### Tutorial panel

Canvas-drawn Pocong illustration (`#tut-canvas`, 172×56): two simple Pocong silhouettes with a red arrow between them. Body text: *"Hantu pocong lompat di sepanjang lorong sebelum masuk pintu acak."* `#tutorial-start` ("→ START") hides once the player has placed a bet. Hidden on mobile (< 768px).

### Mascot canvas

130×130 canvas drawn once. Shows: dark background circle, white burial-cloth oval body, white head oval, black top hat with red band, black dot eyes, sly smile arc. CSS `@keyframes mascot-bob` (translateY 0 → −6px, 2s infinite).

### Win state

`applyWinState()`:
1. Blood splatter opacity → 1.0 on winner room.
2. Red overlay opacity → 0.28 on winner room.
3. Player tokens: winner room → `0x444444`; other rooms → `0xddddaa`.
4. Pocong sprite moves to winner room center.
5. `#win-banner` shown with contextual message.
6. `document.body.classList.add('shaking')` (CSS shake 0.5s, removed after 600ms).
7. `#win-calc` shown if bet outcome is `won`.
8. `#status-outcome` gets class `outcome-won` (color `#c8a800`) or `outcome-lost` (color `#882222`).

`clearWinState()` resets all overlays, banner, win-calc, winnings display, token colors.

## 8. Server API

### Public endpoints (no auth required)

| Method | Path | Description |
|---|---|---|
| GET | `/health` | Returns `{ status: 'ok' }` |
| GET | `/api/game/env` | Returns `{ isStaging: bool }` |
| GET | `/api/game/state` | Returns `{ round, bet, players }` (bet is null if unauthenticated) |

`/api/game/state` response shape:
```json
{
  "round": { "id": 6, "round_number": 6, "status": "active", "winner_room": null },
  "bet": { "room_slug": "library", "amount_tkn": 1000, "outcome": "pending" },
  "players": [{ "username": "alice", "room_slug": "library", "outcome": "pending" }]
}
```

### Authenticated endpoints

| Method | Path | Body | Description |
|---|---|---|---|
| POST | `/api/game/bet` | `{ room_slug, amount_tkn }` | Place bet (one per round per user) |
| POST | `/api/game/advance` | `{ winner_room? }` | Advance round state (admin in prod; anyone in staging) |
| POST | `/api/press` | — | Legacy; unused by current UI |
| GET | `/api/leaderboard` | — | Legacy press leaderboard; unused |

### `/api/game/advance` state machine

```
active → resolving  (first call: sets status)
resolving → completed  (second call: picks random winner room, scores bets, creates next active round)
completed → (ensures next active round exists)
```

In staging, any authenticated user can call advance. In production, only `is_admin` users or username `'admin'`.

## 9. Database schema

All tables use `CREATE TABLE IF NOT EXISTS` — migrations are idempotent and run on every boot.

```sql
-- Legacy (not used by current UI but kept for compatibility)
CREATE TABLE presses (
  id SERIAL PRIMARY KEY,
  user_id INTEGER NOT NULL,
  username VARCHAR(255) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- One row per betting round
CREATE TABLE rounds (
  id SERIAL PRIMARY KEY,
  round_number INTEGER NOT NULL,
  status VARCHAR(20) NOT NULL DEFAULT 'active',  -- 'active' | 'resolving' | 'completed'
  winner_room VARCHAR(100),                       -- null until completed
  created_at TIMESTAMPTZ DEFAULT NOW(),
  completed_at TIMESTAMPTZ
);

-- One bet per user per round (UNIQUE constraint enforced)
CREATE TABLE bets (
  id SERIAL PRIMARY KEY,
  user_id INTEGER NOT NULL,
  username VARCHAR(255) NOT NULL,
  round_id INTEGER NOT NULL REFERENCES rounds(id),
  room_slug VARCHAR(100) NOT NULL,
  amount_tkn INTEGER NOT NULL DEFAULT 1000,
  outcome VARCHAR(20) NOT NULL DEFAULT 'pending',  -- 'pending' | 'won' | 'lost'
  created_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(user_id, round_id)
);
```

Win logic (in `advance` resolving→completed):
- `outcome = 'lost'` if `room_slug = winner_room`
- `outcome = 'won'` for all other rooms

The game is "bet NOT to be in the winner room" — the Pocong enters the winner room and finds anyone who hid there.

## 10. Staging seed data

On boot in staging, if `rounds` table is empty:
1. Inserts round 5 as `completed`, `winner_room = 'kamar-utama'`.
2. Inserts 30 bets across all rooms (8 lost in kamar-utama, 22 won in other rooms).
3. Inserts round 6 as `active`.

All fake users named `staging-user-NN` or `staging-demo-user`. Uses `ON CONFLICT DO NOTHING` for idempotency. Block strictly guarded by `if (IS_STAGING)`.

## 11. Multiplayer polling

```js
setInterval(pollState, 3000);
```

`pollState()` fetches `/api/game/state` every 3 seconds. On change (round ID, status, or players array):
- Calls `clearWinState()` if round changed.
- Calls `placePlayerTokens(players)` to refresh all tokens.
- Calls `applyWinState(state)` if round is completed.
- Calls `refreshOutlineObjects()` to update OutlinePass after scene changes.

```js
fetch('/api/game/env').then(r => r.json()).then(({ isStaging }) => {
  if (isStaging) document.getElementById('dev-controls').style.display = 'block';

```

- **⚡ Resolve Round**: calls `/api/game/advance` twice (active→resolving→completed). Picks a random winner.
- **🔄 New Round**: calls `/api/game/advance` once (completed→next active round). Only shown when `round.status === 'completed'`.

In production these buttons are not rendered. The advance endpoint also guards at the server level.

## 13. Auth flow

Usernode injects a JWT as `?token=` on initial load. Frontend stores it in `authHeaders` and sends as `x-usernode-token` on all API requests. Server verifies with `JWT_SECRET` env var and populates `req.user = { id, username, usernode_pubkey }`.

Public routes bypassing auth: `/health`, `/api/game/state`, `/api/game/env`. All others require a valid token.

## 14. Known issues / what still needs work

### 3D dollhouse not fully resolved

The current implementation has the correct constants (`WALL_H=2.8`, `ROOM_W=ROOM_D=GRID_SPACING=4.0`, `viewSize=16`) and doorway wall helpers, but **the visual still does not match the target spec**. Reported issues:

- Walls may still appear flat or low — verify `WALL_H=2.8` is actually being used in `solidWallGroup()` and `doorwayWallGroupX/Z()`.
- Room spacing gap: if `GRID_SPACING` does not exactly equal `ROOM_W`, a dark gap will appear between rooms. Both must be `4.0`.
- Two directional lights must both be in the scene; one light produces flat shading.
- `OutlinePass` edgeStrength/edgeThickness may need tuning on different screens — try increasing `edgeStrength` up to `8.0` if outlines are still faint.
- The `updateWallsForAzimuth()` function must be called at least once on load (with azimuth=0) to set initial wall visibility, otherwise all walls show simultaneously.

### Deferred features

- Animated Pocong walk cycle (currently static `pocong.jpg` sprite).
- Sound effects (ghost shriek on win, floor creak on hover).
- Round countdown timer.
- TKN balance tracking and deduction (no on-chain integration yet).
- Admin UI to manually set winner room.
- WebSocket real-time updates (currently 3s polling).
- Variable win multiplier display.
- 14th room "Ruang Teater" at `gridX:1, gridZ:3` (currently a corridor tile) — would require adding to `VALID_ROOMS` array in server.js and creating a staging bet for it.
- Mobile tutorial panel collapse to `?` tab icon.

### Other notes

- `public/assets/hatch.png` is not currently referenced in `index.html` (floors use solid `matFloor` color, not a hatch texture). If hatch texture is desired, add it as a `matFloor` map.
- `public/assets/ui-reference.png` is a design reference only — not used in code.
- Legacy `presses` table and `/api/press` + `/api/leaderboard` endpoints exist from the original scaffold. They are unused by the game and can be removed in a future cleanup PR.
- `package.json` does not have a `node_modules/` entry in `files` — always run `npm install` before `npm start` in a fresh environment.

## 15. App-specific conventions

- All TKN amounts are stored as **integers** (not floats). Valid bet tiers: 100, 200, 500, 1000, 5000.
- `winner_room` in `rounds` uses the room slug strings (e.g. `'kamar-utama'`), not IDs.
- `outcome` in `bets` means: `'lost'` = you were in the room the Pocong entered (bad); `'won'` = you were elsewhere (safe). This is counterintuitive — read carefully.
- The `VALID_ROOMS` array in `server.js` is the single source of truth for which slugs are bettable. If a new room is added, update both that array and the `ROOMS` array in `index.html`.
- Do not `git push` — the Usernode harness handles the push after each commit. Just `git commit`.
